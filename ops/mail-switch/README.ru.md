# Первичное переключение Dovecot и Postfix на runit

Это инструмент однократной миграции конкретной проверенной пары контейнеров.
Он использует прежние образы и подготовленные приватные релизы конфигурации.
Обновление образов, Woodpecker-деплой новых конфигураций и Certbot — отдельные
следующие этапы. Этот пакет не является универсальным установщиком почтового сервера.

## Проверенные исходные данные

- Dovecot: `78d852e2f61d5769aaf5ccb8115d2775f43e6524`.
- Postfix: `df0940ecd523cd8828bd18b987ef60afa70606e1`.
- Образы и исходные ID контейнеров закреплены в коде.
- PostgreSQL уже управляется отдельным runit-supervisor. Его установленный код
  и legacy systemd units сверяются с предоставленным архивом по SHA-256.
- Конфигурация и SQL maps проверены пользователем в изолированной паре:
  AUTH/TLS на 587/465, запрет подмены отправителя и relay, поиск получателей,
  доставка Postfix → Dovecot LMTP → временный Maildir.

## Установка и проверка без остановки

Из корня `postfix_ac_image`:

```sh
python3 -m unittest discover -s ops/mail-switch/tests -v
sudo python3 ops/mail-switch/install.py
sudo /usr/local/sbin/ac-mailctl check-legacy \
  --dovecot-release /var/lib/ac-mail/releases/dovecot/78d852e2f61d5769aaf5ccb8115d2775f43e6524-e751a517723238d9 \
  --postfix-release /var/lib/ac-mail/releases/postfix/df0940ecd523cd8828bd18b987ef60afa70606e1-87fd0166d1efb1d2
```

Установка создаёт `down` для обоих supervisor, размещает инструменты и вызывает
только `systemctl daemon-reload`. Она не включает units и не меняет контейнеры,
рабочие конфигурации или legacy launchers. Отличающийся установленный файл не
перезаписывается. Проверка отказоустойчива к повторному запуску до миграции.

`check-legacy` проверяет исходные ID/образы, mounts, адреса, restart policy,
приватность и хеши релизов, здоровье PostgreSQL и старой почтовой пары,
свободное место, отсутствие сторонних работающих контейнеров с общим
почтовым хранилищем и совпадение legacy scripts с проверенным эталоном.
Неожиданное состояние вызывает отказ до остановки.

## Переключение — с перерывом доступности почты

После успешной серверной проверки:

```sh
sudo /usr/local/sbin/ac-mailctl migrate \
  --dovecot-release /var/lib/ac-mail/releases/dovecot/78d852e2f61d5769aaf5ccb8115d2775f43e6524-e751a517723238d9 \
  --postfix-release /var/lib/ac-mail/releases/postfix/df0940ecd523cd8828bd18b987ef60afa70606e1-87fd0166d1efb1d2
sudo /usr/local/sbin/ac-mailctl check
sudo /usr/local/sbin/ac-mailctl status
```

Порядок:

1. Повторная проверка, создание приватного журнала и рабочих копий релизов.
   Dovecot получает read-only конфигурацию и SQL-secret; Postfix — конфигурацию
   с файлами пакета из старого образа и SQL maps `root:postfix 0640`.
2. Блокировки миграции, подготовки релизов и операций PostgreSQL удерживаются
   на протяжении операции. Останавливается только `ac_containers.timer`.
   **`ac_containers.service` не останавливается и не перезапускается:**
   в его cgroup остаются другие контейнеры.
3. Общие start/stop scripts исключают почту по `/etc/ac/managed/mail`.
   PostgreSQL marker сохраняется. Одновременно обновляются его эталонные
   `legacy/start.after` и `stop.after`, чтобы последующий PG-деплой принимал
   актуальные общие scripts. Проверка PostgreSQL не отключается.
4. У старых контейнеров отключается restart policy. Штатно останавливается
   Postfix, затем Dovecot. SIGKILL и `podman --replace` не используются.
5. При остановленной паре копируется `/var/lib/postfix` с владельцами и правами,
   создаётся tar писем, очереди и этих данных в
   `/var/backups/ac-mail/switch-*/mail-queue-data.tar`, проверяется читаемость
   tar и записывается SHA-256. Отдельные mount points в почтовых путях запрещены.
6. Старые контейнеры переименовываются в `*-rollback-switch-*`, сохраняются
   остановленными с restart=no. Новые используют тот же Maildir/queue и образы.
   Postfix больше не получает mount `/var/mail`: доставка только через LMTP.
   Его MAC меняется на `02:ac:10:89:01:d7`, устраняя совпадение с Dovecot.
7. Сначала включается runit Dovecot, затем Postfix. Проверяются ID, mounts,
   права mounts, ограничения, окружение независимо от порядка, сеть и cgroup
   conmon. Проверки TLS на 993/995/587/465, userdb, получателя и запрета relay
   не отправляют письма и не требуют пароля пользователя.
8. Проверяется PostgreSQL. Таймер возвращается в исходное активное состояние,
   незавершённая транзакция снимается только после успешных проверок.

Состояние и рабочие каталоги находятся в `/var/lib/ac-mail/switch-*`.
**Не удалять их как временные файлы:** новые контейнеры используют находящиеся
там конфигурацию, SQL maps и `/var/lib/postfix`. Приватные исходные релизы
остаются отдельно под `/var/lib/ac-mail/releases`.

## Ошибки и восстановление

При ошибке переключения инструмент пытается штатно остановить всех кандидатов,
затем вернуть имена, restart policy старых контейнеров, старые scripts и эталоны
PostgreSQL. Если остановку кандидата подтвердить нельзя, старые контейнеры
**не запускаются**, а `pending-switch.json` сохраняется.

После обрыва процесса или неуспешного отката:

```sh
sudo /usr/local/sbin/ac-mailctl recover
```

Команда работает только при незавершённой транзакции. Она не является откатом
любого уже завершённого деплоя. Отдельный откат после успешной миграции требует
проверки текущего состояния и здесь намеренно не автоматизирован.

Письма и очередь при откате не заменяются архивом: доставленные во время работы
кандидата письма должны сохраниться. Старые и новые процессы не должны работать
одновременно с одними данными. Архив предназначен для отдельного аварийного
восстановления, а не для автоматического откатывания содержимого почты.

В приватных `operation-*/command-errors.log` сохраняются ошибки команд;
`switch-*/transaction.json` содержит этап и inspect исходных контейнеров.
Эти отчёты могут содержать секреты и не предназначены для Git или публикации.
При `MAIL_ROLLBACK_FAILED` не запускайте контейнеры вручную параллельно.

## Управление после миграции

```sh
sudo ac-mailctl status
sudo ac-mailctl check
sudo ac-mailctl stop       # Postfix, затем Dovecot
sudo ac-mailctl start      # Dovecot, затем Postfix
sudo ac-mailctl restart
sudo ac-mailctl reload     # проверка конфигурации, затем reload обоих
```

`stop` оставляет down-файлы, `start` их снимает. Вывод `check` не доказывает
работу внешней доставки, DKIM/SPF/DMARC или всех аккаунтов: отдельные проверки
почтового тракта понадобятся после переключения. Входящие сообщения могут
поступать, как только новый Postfix начнёт работать.

Логи supervisor: `/var/log/ac-dovecot-supervisor/current` и
`/var/log/ac-postfix-supervisor/current`; журналы приложений остаются на прежних
bind mounts. Сертификаты подключены read-only из прежнего каталога Let's Encrypt.
Рабочие конфигурации не подтягиваются из Git автоматически этим пакетом.

## Git и Devuan

После успешной миграции нужно перенести `legacy/*.after` в репозиторий
`ac_containers_service` и зафиксировать изменения, как ранее для PostgreSQL.
Это выполняется после сверки с сервером; установщик не делает commit/push.

Runit scripts отделены от systemd. В текущей Ubuntu их запускают две отдельные
systemd units. Автоматический bootstrap runsvdir для Devuan этим установщиком
не предоставляется: его нужно подключить при переносе сервера и не запускать
два supervisor для одного service directory.

## Проверка разработки

Unit tests проверяют создание контейнеров без замены, сохранение queue,
удаление доступа Postfix к Maildir, синхронизацию эталонов PostgreSQL,
успешную транзакцию, отказ после запуска, кандидата без записанного ID,
запрет запуска originals при неудачной остановке, неизвестный candidate,
таймаут без SIGKILL и синтаксис shell scripts.

В среде разработки не запускались Podman, systemd и настоящая почтовая служба.
Серверный `check-legacy` обязателен до `migrate`.
