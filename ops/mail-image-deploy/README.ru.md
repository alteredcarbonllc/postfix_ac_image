# Контролируемое обновление образов Dovecot и Postfix

Пакет предназначен для уже переведённой на runit пары AC mail.
Он устанавливается из репозитория `postfix_ac_image`, управляет обоими
контейнерами и согласует обновление образов с существующим config CI.
Установка не перезапускает контейнеры. Новых sudo-разрешений для CI нет.
Образы по-прежнему автоматически собираются, проверяются и импортируются;
активация этой проверенной пары выполняется администратором.

## Проверенная пара

- Dovecot: `4f3340e7aca41210ae3292a8d629f9fb34ee6f1d`,
  image `4cb832a8b175d71f3378486a0885d8ebd6c0062b5b2fef9f0451d32e9668f43d`.
- Postfix: `bb9df19a40b3161e55c6d97460450449dd2638bf`,
  image `dac5f06d537914bd8f91f8cc0076dc19c3d27df958ff4f7d544d7bad54c83079`.

Код не выбирает `latest`, не скачивает образы и не подменяет квитанции импорта.
Для следующего обновления надо отдельно пересмотреть исходную и целевую пару:
эта версия инструмента намеренно привязана к уже проверенным image ID.

## Что меняется

`install.py` проверяет SHA-256 трёх установленных модулей, сохраняет их копии
в `/var/lib/ac-mail/image-tool-upgrade-*`, обновляет runtime/config CI и
устанавливает `/usr/local/sbin/ac-mail-image`.

Runtime блокирует обычное управление и config CI при незавершённом обновлении
образов. Внутренние команды runit `run` и `signal-stop` продолжают обслуживать
контейнер, указанный в active.json. Общие блокировки mail и PostgreSQL
исключают одновременные транзакции.

Config CI использует образ из проверенного active.json вместо первоначального
жёстко заданного image ID. Новый release содержит ID образа, на котором был
проверен. Перед применением изменённых файлов проверка повторяется на текущем
активном образе. Поддерживается чтение ранее созданных release-манифестов.
Флаг автоматического деплоя конфигураций сохраняется.

## Установка и предпроверка

После добавления `ops/mail-image-deploy` в main и push:

```sh
cd /root/git/postfix_ac_image
test -z "$(git status --porcelain)"
git pull --ff-only
sudo python3 ops/mail-image-deploy/install.py
sudo /usr/local/sbin/ac-mail-config status
sudo /usr/local/sbin/ac-mailctl check
sudo /usr/local/sbin/ac-pgctl check
sudo /usr/local/sbin/ac-mail-image check
```

`check` проверяет квитанции импорта, image ID, UID/root, CMD, метки, platform,
текущее состояние контейнеров и supervision, управляемые файлы конфигурации,
legacy guards, доступность PostgreSQL, подключения данных, отсутствие иных
работающих контейнеров на тех же данных и свободное место под backup.
Затем текущие настройки с серверными секретами проверяются на новых образах
во временных контейнерах без сети и без подключения рабочих данных.
Закрытые результаты проверки находятся в `REPORT=/var/lib/ac-mail/image-check-*`.
Секреты и эффективная конфигурация в stdout не выводятся.

## Переключение

После успешной предпроверки:

```sh
sudo /usr/local/sbin/ac-mail-image deploy
sudo /usr/local/sbin/ac-mail-image status
sudo /usr/local/sbin/ac-mail-config status
sudo /usr/local/sbin/ac-mailctl check
sudo /usr/local/sbin/ac-pgctl check
```

`deploy` повторяет предпроверку под блокировками. Затем:

1. Копирует текущие каталоги настроек с сохранением прав и symlink.
2. Записывает журнал, останавливает Postfix, затем Dovecot через runit.
3. Проверяет штатное завершение и создаёт холодный tar с mail, spool и
   persistent `/var/lib/postfix`; сохраняет ACL/xattrs/числовых владельцев,
   проверяет чтение tar и пишет SHA256SUMS после синхронизации на диск.
4. Переименовывает прежние контейнеры в `*-rollback-image-deploy-*`.
5. Создаёт новые контейнеры по immutable image ID, сохраняя сеть, опубликованные
   порты, env, limits и существующие подключения данных. Настройки подключаются
   из новых рабочих копий; у Postfix не появляется подключение `/var/mail`.
6. Проверяет созданные контейнеры, обновляет active.json и пути active-config.json.
7. Запускает Dovecot, затем Postfix через runit; проверяет userdb, TLS-порты,
   LMTP target, приём известного получателя и запрет relay без отправки письма,
   supervision, hashes настроек и PostgreSQL.
8. Сохраняет успешный журнал и снимает pending marker.

Ожидается перерыв почтовых подключений на время остановки, резервного
копирования и запуска. Старые контейнеры, настройки и backup остаются на месте.
`--replace`, принудительный SIGKILL, удаление mailbox/queue и `chown -R`
рабочих данных не используются. Установка флага `down` сохраняется на диске
до намеренного запуска соответствующего supervisor.

`makedefs.out` остаётся ссылкой из копии каталога `/etc/postfix` на
`/usr/share/postfix/makedefs.out` нового образа.

## Откат и восстановление

При ошибке после начала транзакции выполняется автоматический откат.
Оба кандидата должны остановиться до запуска хотя бы одного старого контейнера.
При таймауте остановки pending остаётся, старые контейнеры не запускаются.
Кандидат, созданный до записи его ID в журнал, обнаруживается по имени,
transaction label и image ID; неизвестный контейнер не заменяется.

После обрыва процесса или неудачного отката:

```sh
sudo /usr/local/sbin/ac-mail-image recover
```

Эта команда завершает откат pending-транзакции. После успешного обновления
доступен отдельный ручной откат:

```sh
sudo /usr/local/sbin/ac-mail-image rollback
```

Ручной откат разрешён при неизменном active.json и неизменных записях files
в active-config.json; проверяются также фактические файлы на диске.
NOOP config CI может обновлять release/revision: это не запрещает откат.
При откате последние release/revision сохраняются, а пути файлов возвращаются
к настройкам прежних контейнеров. Изменения hashes, путей, владельцев или прав
файлов по-прежнему запрещают этот ручной откат.

Откат возвращает прежние контейнеры и настройки, **не восстанавливает tar поверх
текущих писем и очереди**: так не теряются письма, принятые после переключения.
Tar остаётся отдельной аварийной копией. Старые и новые контейнеры используют
одни persistent данные, но не должны работать одновременно.

Не удаляйте `image-deploy-*`: там находятся подключённые рабочие настройки
новых контейнеров. Не переустанавливайте старые версии mail-switch/config-ci
поверх этих модулей. Установщик текущего пакета допускает повторный запуск,
но отвергает неизвестные изменения модулей.

## Проверки пакета и ограничения

```sh
python3 -m unittest discover -s ops/mail-image-deploy/tests -v
```

37 тестов: импорт и неизменяемость config releases, совместимость config CI,
сохранение подключений, drift, сценарии успеха/ошибок, обнаружение кандидата
после потери ответа create, порядок отката, запрет запуска старых контейнеров
при неудачной остановке и повторная установка без рестартов.

Транзакционные тесты используют модель Podman. В среде подготовки пакета
Podman отсутствует; реальная предпроверка и переключение выполняются на VPS.
Это не доказательство корректности всех сценариев отказа Podman или питания.
Проверки доступности не отправляют письма и не требуют пользовательского
пароля. Уже выполненные image CI проверяют синтетическую доставку и вход.
